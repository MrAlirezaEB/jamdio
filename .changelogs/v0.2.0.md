# v0.2.0 — Decouple queue advance from Liquidsoap prefetch

**Date:** 2026-06-29

## Summary

Fixed the core queue bug where an uploaded track never appeared in "Up next": the now-playing state advanced on every Liquidsoap poll (prefetch), so a freshly uploaded track was promoted straight to `playing` and skipped the visible queue. Queue state now advances only when a track *actually* goes on air, signalled by a new Liquidsoap `on_track` callback.

## Added

- **`queued` queue status** — a track handed to Liquidsoap to buffer (prefetched) but not yet audible. Sits between `pending` and `playing`.
- **`QueueService::reserveNext()`** — marks the first `pending` row `queued` and returns its path for Liquidsoap to buffer, *without* touching now-playing.
- **`QueueService::markStarted(string $file)`** — the real track boundary: retires the outgoing `playing` row to `played`, promotes the matching `queued` row to `playing`, handles fallback/non-queue tracks, and is idempotent against duplicate callbacks.
- **`POST /api/track-started`** endpoint (`LiquidsoapController::trackStarted`, `liquidsoap` middleware) — invoked by Liquidsoap when a track begins; runs the promotion and broadcasts `TrackChanged` + `QueueUpdated`.
- **`Queue` scopes** `queued()` and `upNext()` (pending + queued); migration converting the `status` enum to a string to accommodate the new value.
- **Liquidsoap `on_track` callback** in `radio.liq` that POSTs the started file path to `/api/track-started`.

## Changed

- **`GET /api/next-track`** now only *reserves* the next track (`reserveNext()`) and emits no broadcast — the up-next list is unchanged, so the reserved track stays visible until it truly starts.
- **`QueueService::pendingPayload()`** now returns the `upNext` set (`pending` + `queued`) so a buffered track remains in "Up next" until it goes on air.
- **`radio.liq` polling** throttled to once per ~3s while the queue is empty (was 30+ requests/second), stopping the API-hammering retry loop in `request.dynamic.list`.

## Removed

- **`QueueService::advance()`** — replaced by `reserveNext()` + `markStarted()`. It conflated prefetch with on-air advance, which was the root cause of the bug.

## Files touched

- `app/Services/QueueService.php` — replaced `advance()` with `reserveNext()`/`markStarted()`; `pendingPayload()` uses the `upNext` scope.
- `app/Models/Queue.php` — added `STATUS_QUEUED`, `scopeQueued()`, `scopeUpNext()`.
- `app/Http/Controllers/Api/LiquidsoapController.php` — `nextTrack()` reserves without broadcasting; new `trackStarted()` action.
- `routes/api.php` — registered `POST /track-started`.
- `docker/liquidsoap/radio.liq` — `on_track` → `/api/track-started` callback; throttled empty-queue polling.
- `database/migrations/2026_06_29_000003_add_queued_status_to_queues.php` — `status` enum → string(20).
